# Release configuration audit

The audit covers every configuration constructor member in
[`Configuration_Default_Inventory.md`](Configuration_Default_Inventory.md),
the YAML parser's overrides, production CMake options, and their source
consumers. The inventory includes internal fields so that derived material,
particle, and runtime state cannot be mistaken for user-selectable YAML defaults.
It is generated by compiling the actual constructors, without running a GPU.

## Production defaults

| Control | Default | Meaning / restriction |
| --- | --- | --- |
| Build type | Release | Unless explicitly selected; retains `-O3 --use_fast_math -lineinfo` |
| `FMM_M2L_MODE` | `TF32_TC` | TF32 Tensor Core contraction on SM80+; expansion storage, scaling and final accumulation remain FP64 |
| `FMM_P2P_LOCAL_FP32` | ON | FP32 DEM near-field arithmetic, FP64 storage; SPH compact correction automatically selects FP64 P2P |
| CUDA architectures | CUDA 12.x: `70;75;80;86;87;89;90`; CUDA 13.2: `75;80;86;87;89;90` | Native code plus PTX; Volta requires CUDA 12.x; SM70/75 use SIMT, SM80+ use TF32 Tensor Cores |
| `GRANIT_BUILD_MULTIGPU` | ON | Requires MPI development headers/libraries |
| `GRANIT_ENABLE_OPTIX` | OFF | Optional RT backend; no automatic dependency download when off |
| `ENABLE_PROFILING` / `SPH_DEBUG` | OFF / OFF | Profiling markers now apply to all three solvers; SPH debug is single-GPU diagnostics |
| `BUILD_TESTING` | OFF | Opt-in parser, macro/controller and binary-table regressions; no GPU needed |
| `self_gravity.enabled` | false | Gravity is enabled deliberately |
| `self_gravity.method` | `unified_fmm` | Avoids an implicit quadratic direct-gravity run when enabled |
| `self_gravity.gravity_update_rate` | 2 | DEM/SPH inner steps per macro; SPH CFL is sampled only at closed macro boundaries |
| `self_gravity.gravity_macro_dt` | 0 | Positive seconds instead of an integer cadence; omitted rate then resolves to 1 |
| `unified_fmm.theta_far` | 0.8 | Bundled stencil/operator tables support this value only; other values fail during parsing |
| `unified_fmm.enable_global_projection` | true | Removes aggregate internal force and torque; finite shear replicas forbid projection |
| `unified_fmm.tree_dimension` | 3 | Explicit 2 selects the X–Y quadtree |
| `unified_fmm.tree_depth` | adaptive/auto for DEM and SPH | Omitted FMM block also works; explicit integer without adaptive block selects fixed depth |
| `neighbor.method` / `backend` | `lbvh` / `auto` | CUDA with the default build; an OptiX-enabled build may select RT for supported workloads |
| `damping.enabled` | false | Global damping is opt-in; contact dissipation still comes from the material database |
| `inertial.enabled` / `tidal.enabled` | false / false | No implicit ephemeris/frame forces with empty input paths |
| `shear_box.gravity_images.cutoff_radius` | 0 | No radial cutoff unless explicitly supplied |
| Acceleration limiting | disabled | Splitting plus force clamping remains rejected |

`self_gravity` and `unified_fmm` above abbreviate
`accelerations.self_gravity` and `accelerations.self_gravity.unified_fmm`.
Local Cundall damping requires an explicit cadence of 1. SPH compact softening
limits adaptive depth using the current root extent and smoothing lengths;
an infeasible minimum depth fails explicitly. Single-GPU shear FMM still requires a fixed depth;
distributed shear can use its existing common adaptive controller. An inactive
FMM controller is disabled during parsing, so no dummy FMM block is needed in
non-gravity YAML files.

These settings choose numerical execution modes. Projection controls net force
and torque, not total energy; TF32, FP32 P2P, softening, and RESPA still require
accuracy/timestep checks appropriate to each scientific problem.

For SPH, RESPA also controls CFL cadence when gravity is disabled. At an event,
all K inner steps shorten equally; hydro/constitutive updates still run each
inner step. Step-based checkpoints are deferred to the first closed macro at or
after their interval; final checkpoints are always closed. `gravity_macro_dt`
instead selects a bounded macro duration, recomputing its equal-step count from
each new CFL limit. Optional `io.output.scalar_interval > 0` enables
`sph_macros.csv` with the chosen count, dt, endpoint and gravity/CFL counters.
See [SPH RESPA and restart](SPH_RESPA.md).

## Retained performance and numerical controls

| Group | Defaults retained after tracing consumers |
| --- | --- |
| DEM time | `simulation.time.dt` selects the step in seconds; if omitted, legacy automatic factor 0.2; start/stop 0 and output interval 60 s (a real run must supply its duration) |
| FMM physics | `G=6.67430e-11`; softening `0.01 × minimum radius`; direct-gravity G has the same default |
| FMM allocation | particle headroom 1.2; minimum node estimate 65,536 |
| FMM direct work | leaf threshold 16; internal threshold 64; both have active kernel consumers |
| Adaptive depth | range 6–12; trial interval 32 gravity evaluations; one warmup, four samples, two confirmations, minimum improvement 0.02 |
| Adaptive capacity | headroom 2; growth trigger 0.75; distributed count reset fraction 0.10; mean-epoch-time secondary objective and round-robin trials |
| Neighbors | update frequency 1; Verlet enabled, skin 0.01 m; LBVH skin factor 0.3 and absolute rebuild threshold 0; CLL cell-size factor 1.1 remains an explicit alternative |
| GPU launch | device 0; block size 256 |
| Multi-GPU | disabled in YAML; maximum 8; common Morton ownership true; partition depth 0 resolves to the initial computation depth; halo factor 1.5, capacity factor 2 |
| LET | one-shot push true; shared-bucket minimum savings 65,536 bytes, maximum 8 buckets |
| Balancing | adaptive cost model; calibration interval/half-life 8/8, minimum predicted improvement 0.05; 1,024 bins, imbalance threshold 1.15, minimum interval 50 |
| SPH numerical controls | viscosity 0.1; initial h 0.01 m; target neighbors 64; density mode 0; Shepard filter off; kernel correction on; artificial stress off (epsilon 0.3, exponent 4) |
| SPH timestep/support | CFL 0.3; dt bounds `1e-10..1e-3` s; support factor 2; h bounds `1e-6..1` m; gravity softening length 0 |
| SPH state | damage seed 12,345,678; history off; zero stages/fixed parts; symmetry off; relaxation overrides off |
| I/O | strict input-type checks; checkpoint enabled every 1,000 steps; no forced fresh start, rebootstrap, scalar stream, timing receipt, or gravity-force sidecar by default |
| Optional driving/geometry | shear, rotating frame, external bodies, YORP, acceleration fields, walls and clumps remain explicitly configured; defaults do not prescribe a physical experiment |

Explicit DEM `dt` is checked against the contact critical and orbital limits;
it is used directly or rejected, without factor scaling. The deprecated
`dt_factor` alternative cannot be combined with `dt`. SPH uses its adaptive
seconds-valued bounds. See [timestep migration](YAML_Configuration_Guide.md#timestep-in-seconds).

The SPH example intentionally overrides several numerical defaults for its
lattice; those overrides remain visible. Constitutive properties are required
in `material_database`, not copied from legacy SPH/particle placeholders.
Material-database validation and the existing staged-physics defaults remain
unchanged; see [material database](material_database.md) and
[SPH stages](SPH_Physics_Stages.md). The `displacement_threshold` spelling is
retained because sphere-wall gravity still consumes it as a softening fraction
(default 0.3); it is **not** an FMM tree-rebuild control.

## Removed controls

CMake no longer advertises `BUILD_PLUGINS`, `ENABLE_DEBUG_OUTPUT`, or
`FMM_FLOAT_P2P`. The first two had no source consumers; the last exposed legacy
storage precision while the production P2P arithmetic uses
`FMM_P2P_LOCAL_FP32`. Unused cuBLAS, cuSOLVER, cuFFT and NVRTC link dependencies
were removed; NVTX3 profiling uses the platform dynamic-loader library. The unreachable CPU-mock branch in the optional OptiX
helper was removed; the production package still rejects CPU-mock builds.

cuCollections was removed from the build: the optional CLL map was allocated
but never read by neighbor search. The array-based CLL backend remains usable.

The following accepted-but-ineffective YAML controls were removed from the
parser and configuration records. They now fail explicitly:

| Location | Removed controls |
| --- | --- |
| `unified_fmm` | `node_overallocate_factor`, `p2p_queue_initial_factor`, `p2p_queue_resize_factor`, `m2l_warps_per_block`; unimplemented `p2p_tile_t`/`p2p_tile_s` are also rejected |
| `self_gravity` | `tree_rebuild_interval`; every gravity evaluation rebuilds topology |
| `neighbor` | `verlet_skin_factor`, `use_hash_table` |
| `gpu` | `use_double_buffer`, `texture_memory` |
| `multigpu` | `rebalance_frequency`; timing/imbalance controls own balancing |
| `simulation.rotating_frame` | `settlement`; no stepping controller consumed it |
| `accelerations.fields` | `verify`; flags were never used |
| Sphere walls | `sphere_cohesive_strength`; contact cohesion is material data |
| `io.output` | `damage`, `fields: [flag]`; standard v3 fields are already written; `fields: [gravity_force]` enables the active sidecar |

Gravity cadence controls now have one YAML location under `self_gravity`.
Their former siblings directly under `accelerations` fail with a migration
message. Top-level keys and the FMM/adaptive/neighbor/GPU/damping/output tuning
maps reject unknown keys. Existing explicit compatibility aliases for live
behavior (e.g. `force_tree_type`) are retained and still warn.

## Coefficient asset and verification

The committed [G table](../data/fmm/README.md) contains 3,225,600 unrounded FP32
coefficients, including planar operators, generated by the original FP64
composition. All precision modes load the same validated asset; TF32 rounding
and row padding happen before upload. CMake installs the binary with the
solver. Missing, malformed or corrupt files fail instead of silently selecting
another numerical path.

Run the host regressions with `BUILD_TESTING=ON` and CTest. They exercise omitted
sections, fixed/adaptive depth, RESPA/macro cadence, incompatible local damping
and SPH modes, removed keys, standard templates, all coefficient conversions,
relocated asset lookup and corrupt/missing files. A GPU smoke test also checks
that the initial RESPA snapshot is written after its outer gravity bootstrap;
this audit fixed the former zero-gravity initial sidecar. Reproduce the complete
constructor inventory with:

```bash
python3 tools/audit_config_defaults.py --yaml-include /path/to/yaml-cpp/include
```

The generated inventory is an audit snapshot; regenerate it after changing a
constructor. Numerical smoke-test results and build receipts for this release
are recorded separately in `Release_Defaults_Validation.md`.
